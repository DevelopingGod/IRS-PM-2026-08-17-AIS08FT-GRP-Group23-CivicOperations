# Decision register

| ID | Decision | Alternatives considered | Justification | Trade-off / consequence |
|---|---|---|---|---|
| D-01 | Use both GA (assignment + sequencing) and A\* (routing), each for a distinct job | GA only with straight-line distances; A\* only with greedy dispatch | The guideline is satisfied by implemented, evaluated algorithms; road-following travel times materially change assignments | Two components to validate; A\* kept out of the GA inner loop |
| D-02 | Exact per-agency decomposition | One global GA over all crews | Agency compatibility is a hard constraint and no crew spans agencies, so the decomposition loses nothing | If multi-agency crews appear, sub-problems must be merged |
| D-03 | GA formulation B (explicit routes + unserved pool) | A: permutation + decoder; C: NSGA-II | B gives direct control of locked prefixes, plan diffs, warm starts and priority-targeted operators; A has low locality (hurts stability); C needs an extra selection rule and more run time for dispatch | More operator code; feasibility guaranteed by construction instead of penalties |
| D-04 | Scalar weighted objective with minutes-equivalent units; lexicographic as a limiting case | Pure lexicographic; Pareto front | Interpretable λ_B ("travel minutes per rank-1 request"); the trade-off is explicit and tunable | λ values are research choices → validated grid + sensitivity |
| D-05 | Rank weight transform chosen on validation by a pre-registered rule | Fixed 1/r; using C11 score | C11 position is ordinal; using C11's score would violate the priority rule | The result depends on a modelling choice; the full grid is reported |
| D-06 | Work-time budget capacity; no shifts, no max-job counts | Original shift + `max_jobs_per_shift` model | Requested by the project owner; budget directly limits travel + service; job counts are artificial | Time-of-day realism via agency operating hours (D-07) |
| D-07 | Agency operating hours (option C) | All crews always on duty (A); per-crew availability windows (B) | Keeps night requests realistic (queued to opening) without per-crew shifts | Operating hours are assumptions; real windows may differ (documented) |
| D-08 | New versioned crew rosters (`crews_v2`) sized from train demand; original kept and run as "legacy" | Use original roster only | Original counts are not demand-related (e.g. HPD 7 vs 2 crews per borough), shifts uneven, speeds random | Still synthetic; sized on *sampled-window* demand |
| D-09 | Speed enrichment hierarchy with per-edge provenance | osmnx `add_edge_speeds` defaults | Explicit, testable, uses the verified NYC 25 mph default; no osmnx dependency | Posted speed ≠ travel speed → φ factor + sensitivity |
| D-10 | ALT landmarks + straight-line heuristic (max of the two) | Straight-line only; contraction hierarchies | Straight-line is weak in NYC (most roads 25 mph vs 55 mph max); ALT is still exact and simple | 16 extra Dijkstra runs at start-up (< 1 s) |
| D-11 | Dense matrices by one-to-many Dijkstra rows; A\* for point-to-point and final-route reconstruction | All matrix entries by A\* | Measured: one-to-many is faster for |V|² queries; A\* is optimal for the point queries it is used for | Matrix memory per episode (rows cached per source, cleared per episode) |
| D-12 | Snap to the largest strongly connected component | Nearest node of the whole graph | Guarantees every snapped pair is routable along one-way streets | Points near 541 trap nodes snap a little farther |
| D-13 | Commit at departure + publish threshold + change penalty for stability | Freeze a time fence; replan from scratch | Keeps optionality for not-yet-departed work while avoiding churn for negligible gains | Forced events can still reshuffle plans (measured) |
| D-14 | Hybrid trigger policy, 2-min debounce, 15-min periodic | Replan on every event | Avoids expensive GA runs for insignificant changes | Non-forced changes wait up to one interval |
| D-15 | Deterministic event-replay simulator; no services, brokers or databases | Running web service | Reproducible, testable, sufficient for research and demo | Live deployment needs an orchestrator around the controller |
| D-16 | Offline matplotlib maps from saved plan outputs, only on published material changes | Live web map with tiles | Offline, reproducible, depicts exactly the published plan | Static images; size capped per run |
| D-17 | CPU only, no GPU path | CuPy fitness evaluation | Profiling showed the per-agency instances are small (tens to hundreds of requests); the work is branchy Python (insertion, operators) unsuited to GPUs | None for correctness; GPU not needed |
| D-18 | C11 adapter with shared-root path + vendored hash-checked fallback | Re-implement C11 ranking | Re-implementing would create a competing priority model (forbidden) | Fallback uses catalog urgency as C10 input (documented proxy) |
| D-19 | Exclude `status`, `resolution_action_updated_date`, `log_resolution_hours`, `resolution_valid` in addition to the five listed after-the-fact columns | Exclude only the five | They are also only known after a crew acts | Fewer columns in the replay data |
| D-20 | Copy only the runtime road files (graphml, boundaries, manifest, README) | Copy the whole bundle | gpkg duplicates the graph; the HTTP cache and dist zip are acquisition artefacts | Re-acquisition needs the original bundle |
